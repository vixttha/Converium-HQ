# Converium HQ agent entry point

Read [CONSTITUTION.md](CONSTITUTION.md), [STATE.md](STATE.md), [history/DECISIONS.md](history/DECISIONS.md), [products/README.md](products/README.md), [evidence/README.md](evidence/README.md), [handoffs/LATEST.md](handoffs/LATEST.md), and [roadmap/README.md](roadmap/README.md) before resuming ecosystem work. Resolve the current HQ ref and record the exact commit; treat each product profile as a dated observation, then independently resolve the product's actual branch, issues, PR, release and CI evidence. If a source disagrees, surface the discrepancy and prefer the product's canonical records. Never infer acceptance from test success, an idea record or a stale handoff.

Use the Head → Worker → Validate → Internal Auditor → Head single-lane workflow for authorized HQ development. One active Worker. Owner retains integration/release authority. Read-only context recovery may proceed without product mutations. Do not reopen locked architecture without explicit owner approval. Do not manufacture a mandatory installer, tool dependency, shared service or coordination layer. No product action is authorized by reading HQ. No paid runners, mandatory external agent provider or local execution requirement. Use GitHub public hosted runners for HQ checks. Keep all public records free of private conversation details, tokens, personal identifiers and private session URLs.

When ending an authorized task, record exact source and tested revisions, acceptance criteria, evidence and any unresolved blockers, then update the handoff with the next permitted action. Keep historical records intact; append a superseding decision rather than rewriting history. If unable to access a source, mark it unverified. Fresh-agent recovery itself remains a future milestone, not claimed from this document.
